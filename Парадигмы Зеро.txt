Подход к ТЕСТАМ:

Метод ровно обратен TDD - тесты пишутся не раньше кода, а в последний момент:
-метод представляет авто-генерацию тестов:
—ожидаемый вывод
—получаемый результат первичной механики тестируемого объекта
-ожидаемый вывод оперирует лишь символами
-механика объекта оперирует смыслами

-Если заменить символ Правды и Символ неправды друг на друга в ожидаемом выводе, изменится лишь символьное их обозначение, но не первичное поведение тестируемого объекта (все равно, что всех "Кошек" в математике обозвать "Собаками", а всех "Собак" - "Кошками")

-Глобальная тестируемая функция Метода, генерящая тесты, принимает параметры, указывающие на свойства тестов (например, число корректных символов Правды и число некорректных символов Неправды, подаваемых в итоговый сгенерированный тест)

-Можно вызывать Глобальную тестируемую функцию Метода и проверить потенциально ВООБЩЕ ВСЕ случаи на свете, предполагаемые контекстом механики поведения тестируемого объекта

-Глобальная функция должна стремиться к тому, чтобы способствовать процессу "выправления" устройства механики тестируемого объекта. А именно, каждый генерируемый тест должен совпадать с ожидаемым результатом

—Если Глобальная функция Метода имеет хотя бы один сгенерированный не прошедший тест в конечном итоге (после финального выправления первичной механики поведения тестируемого объекта), это должно быть учтено
—-либо глобально (но тогда есть риск забыть или даже не узнать о том, что нужно учитывать это глобально, например, наложение табу на использование такого случая с такими тестируемыми параметрами)
—-либо локально, что предпочтительнее, причем, вероятно, абсолютно.

-Все это позволяет Глобальной функции Метода предоставить возможность к возможности даже не просто авто-тестирования (автоматической генерации ряда тестов), - а еще и потенциальной возможности авто-"выправления" поведения тестируемого объекта! Впрочем, эта технология еще должна доразработаться.

ДИАЛЕКТ ЗЕРО:

Любая лексема является строкой-элементом, которое можно положить во множество. Даже знаки равенства! Лексемы содержатся в стеке структуры лексем в формате json.


# - комментарий

Пример:

...  # комментарий строки


{} - упорядоченное множество
() - неупорядоченное множество без повторений элементов. Важно, что предпринимается попытка воспринимать группирование тоже как такое множество!


= - императивный вызов Зеро, вопрос ему: "чему равно?" Зеро может формулировать такие вопросы сам себе и сам на них же отвечать. Например, в случаях

—абстрагирования
—прогрессивной и регрессивной дефрагментации
—авто-заменах при вычислении или комментарии (в последнем случае без выигрыша чего-либо)
—тактическом и стратегическом планировании

== - как раз комментарий, банальная замена без выигрыша, абсолютно равносильная

:= - декларативное присвоение

:+= / :-= / :*= / :(/=) работает так же, как и в прочих ЯП, но продолжается и в 

(:^=) / (:(*2+1)=) /

( {set1,set2,set3}(:(:=)=){1,{2,2},(3,3)} )  ==

== ( (set1:=1) , (set2:={2,2}) , (set3:=(3)) )

ПРИМЕР:

( (:=)==(=) ) - все равно в данном оторванном контексте  (у меня уже встретилось в сложном примере) что вызвать присвоение, что задать вопрос Зеро "чему оно равно?"


|()| - размер множества ()

|{}| - размер множества {}


( set(x)set2 ) == ( (set1)(set2) ) - декартово произведение set1 и set2, заключающееся в {}


* - арифметическое произведение

Пример:

set:={1}
N:=5
(set:=set*N) == (set:={1,1,1,1,1})


, - разделитель элементов.

Пример:

(,)(a,b) = {aa,ab,ba,bb}


^ - декартова степень

Пример:

set:={...}
set:=(,^|set|)(set) == (set)^(|set|+1)
set:=(,^(|set|-1))(set) == (set)^|set|


/ - исключение из множества

Пример:

x := {L,M,R}
y := {D,E,U}
z := {B,S,F}

axes := {x,y,z}

elements := x(x)y(x)z \ ( x^2 , y^2 , z^2 )  # исключаем из генерации элементы типа UUL, LRD , ...  # НО! Это не исключит ULU! Тут нужен другой механизм - см. ниже


(⭠^N)self - ссылка на элемент N шагов назад в стеке структуры элементов на том же уровне глубины, если он не первый (иначе выныриваем на 1 уровень вверх в элемент, содержащий данный как дочерний) После выныривания - та же логика.

(⭡^N)self - ссылка на элемент N шагов вверх в стеке структуры элементов

(⭣^N)self - ссылка на элемент N шагов вглубь в стеке структуры элементов. Первый элемент берется текущим, все последующие - первыми на каждом дочернем уровне (если только ссылка не смещалась другими командами навигации ссылки)

(⭢^N)self - ссылка на элемент N шагов вперед в стеке структуры элементов. На том же уровне глубины, если он не последний.

Если ссылка уходит далее имеющихся элементов в строке (вправо или влево), текущий self в текущем контексте == первый для ⭠ или последний для ⭢ элемент строки. НО! если поместить этот объект во внешний контекст, перебор ссылок компенсируется за счет предыдущих элементов внешнего контекста! Опять же, возможна ситуация, когда и в этом случае ссылка обрубится на начале, но тогда можно снова поместить её в еще более внешний контекст, ...

Пример:

( elements:=⭠self ) == ( elements:=elements )

axe := {...}
dim := 100
axes := {axe(^)dim}
elements := ( axes(.^|⭡⭠self|) == axes(.^|axes|) )

els_by_layers := ( elements(x)(,^|⭡⭠⭠self|) == elements(x)(,^|elements|) ) 
# {{U,R,F},{U,R,S},{U,R,B}, ...} - элементы с повторениями слоев с одной оси в одном эле-те
Els_by_ls_N:=|elements|
self_templ = .^(2*Els_by_ls_N)self
(elements.:=self_templ)\(,)  # {{URF},{URS}, ...} == elements


set. - распаковка множества set

Пример:

set:={el1,el2}
set:={set,set}
set. == {el1,el2,el1,el2}  # раскрытие подмножества вниз на уровень глубины 1

set:={el1,el2}
(set:={set,set})^2 == (set:={set,set} , set:={set,set})
set.. == {el1,el2,el1,el2,el1,el2,el1,el2} 
# раскрытие подмножества вниз на уровень глубины 2

set_deepest:={...}
set:=set_deepest
N:=...
(set:={set*N})^|set|
set(.^|set|) == {set_deepest*(N^|set|)}
